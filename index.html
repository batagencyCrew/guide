1. What this work is for

We build AI-powered conversational marketing automations for public random-chat / dating-chat sites (Omegle-likes, etc.). The agents use Bambou's AI model (bambouaibot.com – custom AI chat companions like Lina, Louise) to introduce relevant services and share promotional links with interested users.

Your work as dev:

  1. Reversing websites
  2. Making automations (bots)
  3. General tasks
  4. Other developer work

Most of the work is done using AI – basically vibe coding. You don't have to do everything manually.

2. High-level marketing flow

chat site automation (you build) -> conversation powered by Bambou AI -> relevant promotional link -> interested user explores the service

The purpose is marketing and service discovery, not persuading users to buy a subscription. Users decide whether to visit a linked service or take any further action.

Where direct links are unavailable, an assigned Snapchat account may serve as an intermediate marketing channel.

3. Workflow per site – step by step

  1. Pick a site. Check the shared sheet CHAT ONLINE LIST for untaken sites. Then research the site you picked (SimilarWeb also works for traffic/session-time). After that, SKIP SITES WITH <~15 online users. Ask if unsure. Example starters: Camsurf (text-only), Chatrandom, Chat-fr, Whisperly, Chitchat.gg, Y99.in, etc.
  2. Manual research first – full steps on Research page. Open the site as a normal user. Understand:
    • signup vs guest-chat flow
    • how chat transport works (websocket / polling / HTTP)
    • skip/next behavior, rate limits, captchas, bans
    • average session time via SimilarWeb (Engagement Overview → Average Visit Time) – goal is ~1 real convo per session.
    • whether the site supports sharing promotional links in chat – the marketing flow needs a way for interested users to reach the relevant social profile or service. If links are unavailable and there is no assigned alternative channel, the site is not suitable for this workflow.
  3. Build automation – prototype first:
    • Get the very first working prototype as fast as possible before adding any extras.
    • Prefer pure HTTP (requests, httpx, socketio, beautifulsoup4) when possible.
    • Use playwright / headed browser via xvfb + extensions only as last resort.
    • Must handle skip/next, avoid bot-to-bot matches (e.g. scrape assigned IDs where available).
    • Multithreaded / parallel workers – Bambou calls this "multithreading". Target 50-100 simultaneous accounts per site.
  4. Wire to Bambou AI API (see §6). You will get the list of presets either in the docs or as a response to a specific API call. Use the preset assigned for your site.
  5. Integrate the Dashboard / HUB v2 as well (see setup, v2 documentation, and starter downloads). Run bambou-agent with HUB_URL=https://bamboubot.duckdns.org and your site token, and import the bambouhub Python or Node.js SDK in your script to report workers, logs, metrics, costs, proxy health, config/proxy sync, commands, issues, and backups. The HUB is separate from the Bambou AI API; both integrations are required.
  6. Proxies + hosting. Test with proxies from day one. Don't develop only on datacenter IP then wonder why it gets blocked.
  7. Get a VPS when script is ready. Tell BIPRO/Bambou – Bambou pays for VPS. "Dedicated VPS" here just means: a VPS meant only and only for that very specific site and not for anything else.
  8. Ask your AI agent for VPS specs. At the end of your AI coding chat, ask: "what specs are needed to run at least 50 workers and max 100 workers of this automation?" Send that estimate when requesting the VPS.
  9. Update sheets + handoff. Log progress in the shared sheet. When swapping AI chats, write a short .md handoff so context isn't lost.

Tracking managed by BIPRO / Bambou – you don't need to do anything for it

4. Done per site

A site is DONE when:

  • working automation with successful chatting on the site,
  • successfully using proxies,
  • successfully using the AI API,
  • successfully integrated with the Dashboard / HUB v2: bambou-agent + bambouhub SDK connected, worker health & logs visible, start/stop/restart/pause/set_workers working, config/env/proxies syncing, real metrics/costs/proxy health reported, and cloud backups verified,
  • automation is deployed and in working condition (chatting on all workers/threads) in the VPS given/taken.

No manual demo with your own IP + hardcoded replies = not done.

5. Tech freedom

Bambou only cares about working automations for the sites. Devs have freedom for whatever they do / however they do it.

So one codebase per site, shared tooling, separate repo, whatever – never really thought of, just do what works. "He only wants it working. Doesn't matter how."

  • Hosting VPS are Ubuntu Linux (headless) running on 24.04. No full-desktop RDP assumption. Use systemd services, env files (root-readable) for secrets.
  • Don't commit secrets (keys, proxy URLs, logins) to code. Use env files.

6. AI API & presets

Full reference is in the official docs – read those, don't guess:

  • Site: https://bambouaibot.com
  • Docs: https://bambouaibot.com/api-docs.html
  • OpenAPI: https://bambouaibot.com/openapi.json
  • Routes: GET /api/assistant/presets, POST /api/assistant/generate
  • AI API can be implemented from the docs.
  • You will get the list of presets either in the docs or as a response to a specific API call.
  • API keys and other credentials are NOT given right away – gradually provided as you progress.
  • You don't need to do ANYTHING related to getmysocial – that's our work (integrated into the AI).

6a. Dashboard / HUB v2 — required

Every site automation must integrate with the Bambou Automation Hub v2 as well as the Bambou AI API. The HUB supervises scripts via bambou-agent + the bambouhub SDK (workers, logs, metrics, costs, proxy health, config/env/proxy sync, commands, alerts, and cloud backups); it does not replace the AI API or implement your site's chat logic.

  • Dashboard and public origin: https://bamboubot.duckdns.org
  • Configure bambou-agent with HUB_URL=https://bamboubot.duckdns.org and your site's hst_... token (in /etc/bambou-agent/<site>.conf, mode 0600). Your script talks to the agent over a local Unix socket via the bambouhub SDK and never holds the token.
  • One bambou-agent per site token.
  • Read the HUB v2 integration guide for setup, acceptance checks, the full v2 documentation library, and the download package (agent2/, Python & Node.js SDKs, and templates/v2/ starters).

7. Proxies, VPS, accounts, captchas

All credentials provided separately gradually as you progress.

  • VPS: paid by Bambou. One site = one VPS meant only for that site, nothing else. Request via BIPRO when script is ready, with your 50/100-worker spec estimate. Dev on your own machine, VPS only for hosting.
  • Proxies: prefer mobile 5G proxies (cheaper). Residential as fallback. ANY datacenter IP can get blocked by chatting websites sometimes – test with proxies early.
  • Emails: temp-mail provider (details provided separately when needed).
  • Captchas: solver service (details provided separately when needed). Do captcha-free sites first.
  • Snapchat: only if assigned. Log pre-made accounts into AdsPower profiles and note the username.
  • VPS logins sheet: new logins go in the separate VPS-logins spreadsheet.

8. Hours, pay, reporting

  • Not a company – freelance-style.
  • Normal: 3-4h/day. Busy days: minimum 1-2h is OK if you inform.
  • Pay talked out with Bambou directly. Weekly or monthly – your choice. Rest of salary talks with Bambou.
  • AI credit: if you need it for the job, Bambou can provide (work use only). Own source also fine.
  • Reporting: you report to Bambou. BIPRO only tells you the first few stuff to start.
  • Contact: Bambou on Discord – ask BIPRO for current handle/server.
  • Off-topic tasks possible.

9. How to start

  • Contact Bambou, settle pay (weekly/monthly + amount + method) directly with him
  • Get sheet links + initial credentials (rest comes gradually)
  • Pick 1 site (skip taken/small sites), finish that 1 site first
  • Build prototype fast, meet Done criteria
  • Ask AI agent for 50/100-worker VPS specs, request VPS
  • Deploy in VPS, verify chatting on all workers/threads
  • Update sheet, ask for next site
  • Integrate the Dashboard / HUB v2 (bambou-agent + bambouhub SDK) and verify worker health/logs, lifecycle controls, config/proxy sync, metrics/costs/proxy health, and cloud backups (see HUB v2 guide)

10. Do / Don't

Do:

  • Honesty + loyalty, ship fast (“what can be done today, finish today”)
  • Prototype first, extras later
  • Test as normal user first
  • Update sheets, write handoffs

Don't:

  • Share keys/logins unnecessarily, don't commit secrets
  • Use VPS for anything else except hosting its site
  • Spam team with personal payment issues
